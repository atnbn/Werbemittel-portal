## Muster

Es gibt noch kein Fachmodul. `template` wird das Referenzmodul: Controller → Service →
Repository, DTOs als Records in `dto/`, Mapping über `XxxResponse.from(entity)` im Controller,
fachliche Exceptions in `common`, Abbildung auf Problem Details nur im `@RestControllerAdvice`.

## Abhängigkeitsregeln

- Fachmodule (`template`, `order`, `partner`) dürfen von `security` abhängen, `security` von keinem Fachmodul.
- `common` hängt von keinem Fachmodul ab.
- `seed` darf alle Module kennen; kein Modul hängt von `seed` ab.

## Entscheidungen außerhalb von Spec und ADR

1. Tabelle `users` statt `user` (`USER` ist in H2 reserviert).
2. Seeder als Java-`ApplicationRunner` im eigenen Package `seed` (braucht den `PasswordEncoder`).
3. CSRF aus, keine Sessions.
4. `open-in-view=false` und `@EntityGraph`: Lazy Loading endet im Service.
5. Eine gemeinsame `NotFoundException` in `common`.
6. `detail`-Texte: 401 „Anmeldung erforderlich.“, 403 „Keine Berechtigung für diese Aktion.“, 404 „Vorlage {id} nicht gefunden.“
7. Die Tests laufen gegen die Seed-Daten.
8. `User` speichert nur `partnerId`; der Principal `AuthenticatedUser` trägt username, role und partnerId.
9. 401/403 werden von Entry Point und Access Denied Handler an den zentralen `@RestControllerAdvice` delegiert, damit die Abbildung auf Problem Details nur an einer Stelle liegt.
