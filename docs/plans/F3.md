## Entscheidungen außerhalb von Spec und ADR

1. Prüfreihenfolge PATCH: 401 → 403 → 400 (Body) → 404 → 409.
2. `detail`-Texte: 409 „Statuswechsel von BESTELLT nach VERSENDET ist nicht erlaubt.“;
   `"FOO"` → bestehendes „Request-Body ist ungültig.“; fehlender Status „Status fehlt.“;
   404 bestehendes „Bestellung {id} nicht gefunden.“
3. Technische Bezeichner außerhalb des Glossars: `InvalidStatusTransitionException`, `UpdateOrderStatusRequest`.
4. Übergangsregel in `OrderStatus` (ADR); `Order.changeStatus` fragt sie nur ab.
5. Statuswechsel unter pessimistischer Sperre (`findByIdForUpdate`), damit ein paralleler Wechsel den Status nicht zurücksetzt.

## Phase 3: Rot-Nachweis

Damit die Tests kompilieren, wurde vorab nur die Signatur `OrderStatus.canTransitionTo` angelegt,
die vorerst `UnsupportedOperationException` wirft. Controller-Endpunkte, Service, Repository-Methoden,
Security-Regel, Exception und Handler fehlen noch. `TestDataChangeRepository.changeUpdatedAt`
(native Query) läuft bereits fehlerfrei (Assert `== 1` in `ak13_zentraleSetsStatusToInProduktion` grün).

24 rote Tests, keine Kompilier- oder Konfigurationsfehler; alle 53 bestehenden Tests aus F1/F2 bleiben grün.
